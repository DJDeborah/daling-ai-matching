# 妲灵：商业化与留存诊断

更新：2026-10-04。[项目与截图](../README.md) · [网页版](https://daling-ai-matching-smile.harebod.chatgpt.site/)

## 先说判断

当前最值得验证的是：**妲灵能否帮助用户认识一个愿意回应的真实对象。**

当前访谈、结构化档案和分析能交付一次完整体验。持续价值还需要真实供给、双方回应，以及交流之后的新进展。继续优化插画、问卷或报告，单独不能证明这条需求成立。

这是基于代码流程的产品判断，不是已验证的流失归因；本次没有读取生产用户数据，仓库也未提供收入或 cohort 数据。

## 证据边界

| 类型 | 能确认什么 |
| --- | --- |
| 验证目标 | 首次介绍后的继续使用、现实交流价值与实际支付 |
| 代码事实 | 先注册，再进行访谈；新访谈有 10 个主题，可提前停止 |
| 代码事实 | 报告突出实验首位；实验人物无法心动或联系 |
| 代码事实 | AI 文字分析目前只处理实验候选 |
| 代码事实 | 真实心动及联系方式位于独立资料页面，未见会面反馈、候选通知或收费闭环 |
| 测量限制 | 未见访问／介绍／会面产品事件，无法仅从源码计算用户留存率 |
| 待验证假设 | 首次投入过高、结果无法行动、缺少新的回访价值 |

代码依据：[报告展示](../app/chat-app.tsx)、[AI 分析输入](../lib/report-ai.ts)、[真实资料交互](../app/matching-app.tsx)、[数据模型](../db/schema.ts)。没有读取生产真实池人数，不能断言真实池为空。

## 三个优先假设

| 假设 | 验证方式 | 看什么 |
| --- | --- | --- |
| 用户得到了报告，却没有可交流的对象 | 在商业化试验中先介绍一位真实、活跃且愿意被介绍的人 | 接受介绍及实际双向交流 |
| 首次投入早于价值兑现 | 对比 10 题与先 3 题、接触后逐步补深度信息；两组仍要求账号 | 到真实介绍的完成率、耗时和交流质量 |
| 看完后没有回来做的新事情 | 将交流反馈用于下一次介绍，仅在有新介绍或回应时通知 | 仍在寻找者是否主动请求或回应第二轮 |

要先测到用户在哪个阶段离开。注册前离开、答题中止、报告后离开、介绍无人回应和付费拒绝，对应不同问题，不能合并成“网站不够好看”。

## 优先验证的定位

**一个已有真实成员的同城小社群，每周帮助认真恋爱的人认识一位双方愿意继续了解的对象。**

先限定城市、社群和明确年龄段，人工确认参与意愿与活跃状态。妲灵帮助表达关系期待、解释介绍理由、设计破冰问题，并收集反馈。初期无需全国平台或复杂自主 Agent。

这个方向便于同时观察供给覆盖、双方回应和付费意愿。它仍是待验证定位，不保证成功。

深度比较适合说明可能的共同点和要沟通的差异。它暂不具备预测关系成功的证据。2023 年一项预注册研究跟踪 208 名单身者、1,065 名潜在对象，未发现该研究的理想伴侣偏好匹配对浪漫兴趣的支持；不能直接推广到所有产品或否定全部 AI，但足以要求谨慎定位评分。[原始论文](https://pscresearch.faculty.ucdavis.edu/wp-content/uploads/sites/112/2024/11/eastwick-blozis-2023-predicting-romantic-interest.pdf)

## 14 天、小规模真实介绍试验

**建议 40 名自愿参加的同城成年人。**首先检查双方基本条件形成的可用供给，至少 32 人各有一位活跃且符合双方条件的候选。缺供给时先招募，暂不扩大投放。

| 时间 | 工作 |
| --- | --- |
| 第 1–2 天 | 招募、确认参与意愿、必要条件、可介绍供给覆盖 |
| 第 3–4 天 | 随机各 20 人，比较 10 题与 3 题后补充；交付相同的真实介绍服务 |
| 第 5–7 天 | 收集是否接受、是否开始双方交流、是否计划见面 |
| 第 8–10 天 | 给仍在寻找者第二轮真实介绍，收集简短反馈 |
| 第 11–14 天 | 双方确认见面与继续了解的结果，访谈退出者；可交付下一轮时测试明码标价的付费服务 |

实验档案不参与真实介绍。只记录双方自愿报告的交流结果，不读取私人聊天或默认分享反馈。

### 必须记录的漏斗

```text
进入 → 注册 → 开始访谈 → 必要资料齐全 → 收到真实介绍
     → 接受 → 双方交流 → 见面 → 愿再见
     → 请求下一轮 / 成功暂停 / 无价值退出 → 实际付费
```

记录来源、首次时间、介绍批次和参与状态，保持原始 cohort 分母。不能把 AI 调用次数、登录会话或页面停留时长代替真实交流结果。

### 预先约定的决策门槛

以下是建议的内部试验门槛，**不是行业基准或统计验证**：

- 至少 32/40 人收到合格真实介绍。
- 获得介绍者中至少 40% 进入双方实际交流；同时记录不同交流配对数，避免重复计数。
- 至少 4 对不同参与者双方确认已见面。
- 仍在寻找、且收到第二轮合格介绍的人中，至少 40% 请求或回应第二轮。
- 下一轮可真实交付时，至少 5 人实际支付统一测试价；没有真实收费，本轮不能证明商业化。
- 记录每次交流／会面的 AI 和人工成本，检验测试价格能否覆盖交付成本。

40 人只适合寻找信号和暴露问题。两组差异用作下一轮方向，不能宣传某项改动显著提升留存。

### 停止或调整

- 供给覆盖低于 80%：暂停推广，先解决招募和可介绍人数。
- 覆盖足够但双向交流低于 20%，或没有任何双方确认的见面：暂停堆功能，访谈拒绝者并重新评估定位。
- 交流有价值但无人支付：继续验证交付与付费对象，暂不推出订阅。
- 反馈指出不可信、骚扰或错误介绍：优先修正具体交付与运营问题，再扩大规模。

## 留存要区分成功退出与失败流失

| 观察 | 解释 |
| --- | --- |
| 认真继续了解某位对象，主动暂停寻找 | 确认后记为成功进展 |
| 转到微信交流，少回网站 | 渠道转移；尚不能自动算完全成功或失败 |
| 看完实验报告，没有得到真实可联系的人 | 核心价值未兑现的流失风险 |
| 介绍不合适、无人回应、用户放弃 | 介绍质量或供给问题 |
| 当前没有恋爱需求 | 需求暂停 |
| 联系不到，未反馈 | 未知 |

同时报告原始 cohort 整体回访、仍在寻找者的第二轮行动和成功进展人数，避免通过剔除退出者美化留存。

## 可参考的外部证据

- Hinge 的 “We Met” 在交换联系方式后询问是否见面、是否愿意再见，并用于后续推荐。这是值得参考的结果反馈流程，不证明它一定适合妲灵。[官方说明，2026 年更新](https://help.hinge.co/hc/en-us/articles/360010692913-What-is-We-Met)
- Hinge 自报限制未回应对话的试验提高了回复表现；公开材料没有足够细节可转移其提升幅度。[官方试验介绍](https://hinge.co/newsroom/your-turn-limits)
- SSRS 2025 年对 2,016 名美国成年人进行概率抽样，曾使用约会产品的人中 57% 将相似家庭价值视为非常重要。它提示深度期待可能有需求，不能证明中国用户愿意答题或支付。[调查与方法](https://ssrs.com/insights/the-public-and-online-dating-in-2025/)
